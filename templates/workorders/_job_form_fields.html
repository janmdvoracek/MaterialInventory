{% comment %} The body of the Zpracování form: the job's own fields, then the four formset sections. Shared by transform_form.html (recording a job) and job_edit.html (a manager correcting one), so a field added to a row cannot land on one page and be forgotten on the other. The two views already share `_collect_rows` and `_write_job_rows`; this is the markup half of the same rule. Rendered inside the caller's own
, so there is no tag, no {% csrf_token %} and no primary submit button here — those differ per page and stay with the caller. The „+ další řádek" buttons *are* here, one per section, because they belong to the rows they grow. Each is a plain submit that posts the form back under `add_`; the view rebuilds the page unbound with one more blank row and renders it. That is the whole mechanism — there is no JavaScript in this app, and a formset otherwise renders a fixed number of rows and no way past them. They carry `formnovalidate` because „Moje hodiny" and „Datum provedení" are required, and without it the browser would refuse to submit a half-filled form and the button would silently do nothing. Because the browser submits a form via its *first* submit button when Enter is pressed in a text field, and these come before the caller's real one, each caller opens its with an off-screen decoy submit so Enter still saves. „Zapsat za" is guarded because it is manager-only: `job_edit` builds `WorkOrderForm` without a `user`, so the field is simply not there.
