{% comment %} The body of the Zpracování form: the job's own fields, then the four formset sections. Shared by transform_form.html (recording a job) and job_edit.html (a manager correcting one), so a field added to a row cannot land on one page and be forgotten on the other. The two views already share `_collect_rows` and `_write_job_rows`; this is the markup half of the same rule. Rendered inside the caller's own
, so there is no tag, no {% csrf_token %} and no primary submit button here — those differ per page and stay with the caller. The two row buttons *are* here, one pair per section, because they belong to the rows they resize. Each is a plain submit posting the form back under `add_` or `remove_`; the view rebuilds the page unbound with one more blank row, or one fewer row, and renders it. That is the whole mechanism — there is no JavaScript in this app, and a formset otherwise renders a fixed number of rows with no way past them in either direction. Both carry `formnovalidate` because „Moje hodiny" and „Datum provedení" are required, and without it the browser would refuse to submit a half-filled form and the buttons would silently do nothing. „− odebrat řádek" drops the *last* row — the exact one „+ další řádek" adds — and is hidden once a section is down to a single row, so it is never shown as a button that does nothing. The view holds the same floor regardless of what the POST asks for, so hiding it is presentation, not the rule. Because the browser submits a form via its *first* submit button when Enter is pressed in a text field, and these come before the caller's real one, each caller opens its with an off-screen decoy submit so Enter still saves. „Zapsat za" is guarded because it is manager-only: `job_edit` builds `WorkOrderForm` without a `user`, so the field is simply not there. The hours label comes from the form rather than being written out, because each page means something different by it — see `WorkOrderForm.__init__` and `job_edit`. **Every error this page can produce is rendered, and that is a rule rather than a nicety.** Nothing here is written unless all five forms validate, so an error with nowhere to appear is a submission that vanishes: the page comes back carrying what was typed, with no message anywhere, looking exactly as if the button had not been pressed. That is what used to happen to any *field* error on a row (`_row_errors.html` now covers those), to a formset's `non_form_errors`, and to the job form's own `description`/`author`/`non_field_errors`. {% endcomment %} {# The job's own errors, same rule as the rows below: anything that refused the #} {# submission has to be readable, or the page just comes back looking ignored. #} {% for error in order_form.non_field_errors %}
