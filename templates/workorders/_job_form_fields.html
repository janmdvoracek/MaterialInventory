{% load static %}{% comment %} The body of the Zpracování form: the job's own fields, then one block per `JOB_SECTIONS` entry (`sections` in the context, from `_job_context`). Shared by transform_form.html (recording a job) and job_edit.html (a manager correcting one), so a field added to a row cannot land on one page and be forgotten on the other. Rendered inside the caller's own
, so there is no tag, no {% csrf_token %} and no primary submit button here — those differ per page and stay with the caller. Because the browser submits a form via its *first* submit button when Enter is pressed, and the row buttons below come before the caller's real one, each caller opens its with an off-screen decoy submit so Enter still saves. Each section's two row buttons are plain submits posting the form back under `add_` or `remove_`; the view rebuilds the page unbound one row bigger or smaller (`_job_forms`). Both carry `formnovalidate`, or the browser would refuse to submit a half-filled form and the buttons would silently do nothing. „− odebrat řádek" is rendered `hidden` once a section is down to one row rather than left out, because job_rows.js toggles it back; the view holds the same floor regardless, so this is presentation, not the rule. **job_rows.js resizes a section in the DOM instead, and is pure enhancement** — it intercepts those two clicks, and with the script missing the submits above still work. It is loaded from this partial rather than from base.html or the two callers for the same reason the fields live here: the pages cannot drift, and the other four do not load it. The JS builds no markup of its own; it clones the per-section
